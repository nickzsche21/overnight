Caps that actually stop

Vercel

Set a spend amount and turn on Pause Production Deployments. It checks every few minutes, so expect a few minutes of overshoot, and it does not cover AI Gateway or v0 usage. docs

Anthropic & OpenAI

Set an organization or project spend limit near what you can afford to lose — not your monthly forecast. Anthropic · OpenAI

Google Cloud

Ordinary budgets only alert. Look for spend cap budgets (preview) on services that support them. docs

AWS & Azure

No hard cap. You can wire alerts to automation that shuts things down, but it fires on the same delayed billing data — hours late by design. AWS · Azure

Or put the cap in your own code

For anything that calls an LLM API, the only cap with no lag is one in the same process. This counts the cost of each response from its own usage numbers — Anthropic and OpenAI shapes, cached tokens included — and refuses the next call before it is made once you are at your cap. No dependencies. Tested: a runaway agent loop stops within one request of the cap.

Prompted by the October 2026 argument — Simon Willison, and the thread — that hard budget caps should be the default. Everyone agreed alerts arrive late; nobody put a number on how late, or what it costs.

  
Delays are modelled from each provider's own documentation, linked beside it. Where a document says “several hours” the page says what it assumed. Prices in the scenarios are examples: set your own. This is a model of the documented worst and typical cases, not a measurement of your account.
